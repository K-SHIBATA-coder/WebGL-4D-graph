# 4Dグラフ描画

4変数方程式、複素関数・複素方程式、リーマンゼータ関数を点群として計算し、WebGL2で表示する学習用プログラムです。4D回転、複数の4D→3D投影、log・arg表示を切り替えて観察できます。

## 起動方法

必要なものはPython 3.10以降、SymPy、WebGL2対応ブラウザーです。SymPyをまだ入れていない場合:

```bash
python -m pip install sympy
```

1. `4D_generate.py`を実行して通常の方程式・複素式の点群を作ります。
2. リーマンゼータ関数を表示したい場合は`4D_zeta_generate.py`も実行します。
3. このフォルダーでローカルWebサーバーを起動します。

```bash
python -m http.server 8000
```

4. ブラウザーで <http://localhost:8000/> を開きます。HTMLを直接開く方法では、JSONやバイナリを読み込めません。

## 操作

- キャンバスをドラッグしてカメラ視点を動かします。視点は真上・真下まで移動できます。
- 円形スライダーで4D回転を調整します。連続回転ボタンで回転を継続できます。
- 「回転前の点に戻す」「カメラ位置をもとに戻す」で各状態をリセットします。
- 表示方法ボタンで、色を使った表示、log・arg、正四面体方向への投影、正八胞体型を選びます。
- log・arg表示では入力と出力を入れ替えられます。また「高さ0の色付き平面にする」を選ぶと、logの高さを0に固定し、偏角を色で示します。この平面表示では4D回転・カメラ回転・照明を停止し、表示範囲を正方形の枠で示します。
- 黒い点は、複素微分の停留点としてSymPyが解を特定できた位置です。全ての式で記号的に解けるとは限らないため、検出できた点だけを表示します。
- ゼータ関数表示では、臨界線Re(s)=1/2を紫色で表示します。

## 式・範囲を変更する場所

`4D_generate.py`の`USER EDIT HERE`にある`function(p)`で式を選びます。使用する`return`を1つだけ有効にします。実数式は4変数方程式、複素数を返す式は複素関数または複素方程式として分類されます。SymPyで解析するため、三角関数などは`math.sin`でなく`sp.sin`のように書きます。

- 通常式の範囲・分割数: `IMPLICIT_MIN`、`IMPLICIT_MAX`、`IMPLICIT_GRID_STEPS`
- 複素式の入力範囲・分割数: `COMPLEX_PARAM_MIN`、`COMPLEX_PARAM_MAX`、`COMPLEX_GRID_STEPS`
- ゼータ関数の範囲・分割数: `4D_zeta_generate.py`の`SIGMA_MIN/MAX`、`T_MIN/MAX`、`GRID_STEPS`
- カメラ初期視点、点の大きさ、色: `main.js`と`shader/`
- 画面レイアウト: `index.html`と`css/style.css`

範囲や式を変えた後は、該当するPython生成コードを再実行してください。分割数を上げると点数と計算時間が大きく増えます。

## 注意点と負荷

- **描画範囲の外にある解は生成されません。** 点群生成は設定した有限範囲を格子状に調べます。式を満たす点でも、その範囲外にある点は見つかりません。必要なら各変数の範囲を広げて再生成してください。範囲を広げると同じ分割数でも格子が粗くなるため、細部が抜けることがあります。
- **分割数は少しずつ上げてください。** 四変数方程式は有効な変数が4個なら格子値の計算量がおよそ`(分割数+1)^4`で増えます。たとえば48から64へ上げると、格子点だけで約3.1倍です。3変数以下の式では有効な次元数に応じて増え方は小さくなります。複素関数の2次元格子はおよそ`(分割数+1)^2`で、512から1024へ上げると約4倍です。まず低い分割数で形を確かめ、必要な場合にだけ上げてください。
- **点が増えるとブラウザーも重くなります。** 点群の保存容量だけでなく、WebGLバッファ、法線計算、一フレームごとの描画にも時間とメモリを使います。式の複雑さや分岐数によっても生成時間は大きく変わります。
- **法線の向きが場所によって反転することがあります。** 投影後の点群から法線を推定するため、折り返し、枝の切り替わり、点の欠落などで向きが一貫しない場合があります。明るさの下限をシェーダーの`minimumLight`（現在は`0.7`）で設定し、法線が光と反対を向いても色が極端に暗くならないようにしています。値を上げると面全体は明るくなりますが、陰影の差は弱まります。
- **暗い色が法線以外から生じる場合もあります。** 通常の色表示では負のWをグレースケール、W=0を黒で表すため、色の規則自体で暗く見える領域があります。照明の下限を上げても、色の割り当てによる暗さは残ります。
- **回転が遅くなる主因は、通常はバイナリ形式ではありません。** バイナリは起動時の点群読込とJSON解析を軽くします。回転時には点群全体を変換し、GPUからCPUへの読み戻し、投影後の法線再計算、WebGLバッファ更新も行います。そのため分割数や点数が大きいほど回転操作も重くなります。実装ではスライダー入力を画面更新ごとにまとめ、回転計算のGPU読み戻しを位置データだけに絞っています。ドラッグ中と連続回転中は、重い法線と重複点の再計算を保留し、操作後に一度だけ更新します。そのため操作中は一時的に陰影や重なった点の表示が厳密でないことがあります。連続回転は処理量を抑えるため最大約30回/秒に制限しています。
- **特異点や数値的に扱えない場所は除外されることがあります。** 特異点付近は安全のため計算から除外し、有限でない値を返す点も描画しません。式が数学的に解を持つことと、この有限格子で数値点として検出できることは別です。

## ファイルについて

- `main.js`と`shader/`: WebGL表示、回転、投影、色計算
- `4D_generate.py`: 通常式、複素関数、複素方程式の点群生成と停留点探索
- `4D_zeta_generate.py`: ゼータ関数と臨界線の点群生成
- `pointcloud_io.py`: 生成スクリプトで共用するバイナリ書き込み処理
- `data.json`、`zeta_points.json`: 式・範囲などのメタデータ
- `data_*.bin`、`zeta_points_*.bin`: 数値点群。JSON内で指定されたバイナリと必ず組にして保管してください
- `LICENSE`: MIT License
- `CHANGELOG.md`: リリースごとの変更記録

`4D_generate.py`または`4D_zeta_generate.py`で点群を再生成すると、どのJSONからも参照されなくなった古い`data_*.bin`または`zeta_points_*.bin`を削除します。現行のJSONやほかのJSONが参照しているバイナリは残します。
