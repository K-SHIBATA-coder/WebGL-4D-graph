# 4Dグラフ描画

4変数方程式・複素関数/複素方程式・リーマンゼータ関数を点群として計算し、WebGL2で3D表示する学習用プログラムです。4次元の回転、複数の4D→3D投影、点群の自動縮尺を試せます。

## はじめて使うとき

### 必要なもの

- WebGL2に対応した最近のブラウザー
- Python 3.10以降を推奨
- 通常方程式の生成時のみSymPy

SymPyをまだ入れていない場合、ターミナルで次を実行します。

```bash
python -m pip install sympy
```

### 点群の生成

このフォルダーをターミナルで開き、表示したいデータを生成します。

```bash
python 4D_generate.py
python 4D_zeta_generate.py
```

通常の方程式・複素関数・複素方程式は、式や範囲などの説明を`data.json`、点の数値を`data_日時_識別子.bin`に保存します。リーマンゼータ関数は`zeta_points.json`と対応する`zeta_points_日時_識別子.bin`に保存します。JSONにはJavaScriptへ渡す式名・モード・範囲・特異点情報が残り、数値点群だけがバイナリになります。大きな分割数では計算・保存に時間がかかるため、進捗表示を確認してください。

### ブラウザーで開く

HTMLをファイルとして直接開かず、プロジェクトのフォルダーでローカルサーバーを起動します。

```bash
python -m http.server 8000
```

ブラウザーで <http://localhost:8000/> を開きます。サーバーを止めるときはターミナルで`Ctrl+C`を押します。

## 画面の操作

- **キャンバスのドラッグ**: カメラ視点を回転
- **円形スライダー**: 対応する4D平面を回転。つまみを離すと現在の点位置を保存
- **連続回転**: 同じ平面の連続回転を開始/停止
- **回転前の点に戻す**: 4D回転を初期状態へ戻す
- **カメラ位置をもとに戻す**: カメラ視点を初期状態へ戻す
- **表示方法ボタン**: 色を使った通常表示、log|y|・arg(y)、正四面体方向への投影、正八胞体型を切り替える
- **データを切り替え**: 通常の点群とゼータ関数点群を切り替える

log・arg表示は複素データでのみ選択できます。表示中の式と点数はキャンバス横のステータスに表示されます。

## 自分の式・表示範囲を変える場所

コード中の `USER EDIT HERE` / `USER SETTINGS` / `DISPLAY SETTINGS` を検索してください。主な編集場所は次のとおりです。

| 変更したいもの | ファイルと場所 |
|---|---|
| 描画する通常式・複素式 | `4D_generate.py` の `function(p)`（`USER EDIT HERE`） |
| 通常式の範囲・分割数 | `4D_generate.py` の `IMPLICIT_MIN/MAX`, `IMPLICIT_GRID_STEPS` |
| 複素関数の入力範囲・分割数 | `4D_generate.py` の `COMPLEX_PARAM_MIN/MAX`, `COMPLEX_GRID_STEPS` |
| ゼータ関数のσ,t範囲・分割数 | `4D_zeta_generate.py` の `SIGMA_MIN/MAX`, `T_MIN/MAX`, `GRID_STEPS` |
| カメラ初期視点・点サイズ | `main.js` 内の `DISPLAY SETTINGS` コメント |
| 表示・回転・投影・自動縮尺の仕組み | `main.js` と `shader/` 内のシェーダー |
| 色の計算 | `shader/fragment.frag` の `COLOR MAPPING` 区画 |
| 画面レイアウト・見た目 | `index.html` と `css/style.css` |

**式の変更手順:** `4D_generate.py`の`function(p)`を開き、使う`return`を1つだけ有効にします。実数式は4変数方程式、複素数式は複素グラフまたは複素方程式として分類されます。SymPyで記号計算するため、三角関数などは`math.sin`でなく`sp.sin`のように書きます。式表示用の`IMPLICIT_EQUATION_TEXT`と`COMPLEX_EQUATION_TEXT`は実際の式から自動更新されます。

**計算範囲:** 基本の既定値は各入力軸[-5,5]です。ゼータ関数の既定値は`4D_zeta_generate.py`内で設定します。大きな範囲を使う場合、分割数も上げる必要がありますが、計算点数は急増します。まず低い分割数で形を確認し、必要に応じて増やしてください。

## 色の見方と色方式について

現在、複素出力の`arg`や偏角は周期量なので、色相環を一周して表示します。一方、正四面体型・正八胞体型の4Dベクトル長の色は、現在の実装では一定値ごとに色相環を繰り返します。そのため異なる大きさが同じ色になることがあります。

大小を一意に読み取りたい用途では、単に飽和関数に置き換えるより、**値に対して単調に進む多色グラデーション**と数値凡例を使うのがおすすめです。飽和関数は大きな値が上限色へ近づき、値の差が視覚的にほとんど判別できなくなるためです。例えば、表示範囲の下限・上限へ自動正規化し、暗い紫→青→緑→黄のような順序色を割り当てると、周期色相より大小関係を保てます。値の幅が何桁もある場合は`log(1+x)`型の前処理を加えると、小さい値の違いも残しやすくなります。

どの方式でも、色だけで正確な値を読み取ることは難しいため、採用時には「色と数値の対応」「自動縮尺範囲」を画面に表示する凡例を付けると使いやすくなります。現時点では、既存の周期色相表示を維持しています。

## ファイル構成

```text
index.html                 画面部品とCSS/JavaScriptの読み込み
css/style.css              レイアウトと操作パネルのスタイル
main.js                    JSON読込、回転、カメラ、自動縮尺、WebGL制御
shader/vertex.vert         点の4D→3D投影と頂点処理
shader/fragment.frag       点の色・明るさの計算
shader/axes.*              軸の描画
shader/background.*        背景メッシュの描画
shader/rotate.*            回転用WebGLプログラム
4D_generate.py             通常式・複素式の点群生成
4D_zeta_generate.py        リーマンゼータ関数の点群生成
pointcloud_io.py            共通バイナリ形式の書込処理
data.json                  通常式・複素式の表示情報（JSON）
data_*.bin                 通常式・複素式の数値点群
zeta_points.json           ゼータ関数の表示情報（JSON）
zeta_points_*.bin          ゼータ関数の数値点群
```

生成時に`.bin`ファイルが新規作成され、JSONメタデータはそのファイル名を参照する形で更新されます。メタデータJSONと、その中の`binary.file`に書かれたバイナリファイルは必ず一緒に保管・公開してください。古い`.bin`は、対応するJSONメタデータが参照していないことを確かめてから削除できます。どちらも手動編集は不要です。`data.json.tmp`のような一時ファイルが残った場合は、生成処理が途中で止まった可能性があります。JSONをブラウザーで使っている間に再生成すると、同期ソフトやウイルス対策ソフトがファイルを一時的にロックすることがあるため、ブラウザーのタブを閉じてから再実行してください。

## ZenodoでDOIを付けて公開する方法

簡単なのはGitHub連携です。GitHubを使わない場合は、ZenodoへZIPを直接アップロードできます。

### GitHub連携（おすすめ）

1. 公開用GitHubリポジトリを作り、README、ソース、`LICENSE`、必要な生成データを登録します。
2. Zenodoへサインインし、GitHubアカウントを接続します。
3. ZenodoのGitHubページでリポジトリ一覧を同期し、対象リポジトリを有効にします。
4. GitHubに`v1.0.0`のようなReleaseを作成します。有効化済みのリポジトリでは新しいReleaseがZenodoへ自動取り込みされ、レコードとDOIが作成されます。
5. Zenodoのレコードページでファイル、著者名、ライセンス、説明を確認します。以後の版もGitHub Releaseごとに記録されます。

公式ガイド: [GitHubリポジトリの連携](https://help.zenodo.org/docs/github/enable-repository/)、[ソフトウェア情報の記述](https://help.zenodo.org/docs/github/describe-software/)、[GitHub Releaseのアーカイブ](https://help.zenodo.org/docs/github/archive-software/github-upload/)。

`CITATION.cff`をリポジトリに用意すると、引用情報の整備に役立ちます。ZenodoのGitHub連携では、`CITATION.cff`と`.zenodo.json`の両方がある場合、`.zenodo.json`が優先されます。

### ZIPを直接アップロード

1. Zenodoで **New upload** を選び、公開対象のZIPをアップロードします（[公式の新規アップロード手順](https://help.zenodo.org/docs/deposit/create-new-upload/)）。
2. Resource typeをSoftwareにし、タイトル、作者、説明、ライセンスなどのメタデータを入力します。
3. 必要ならDOIを予約します。予約だけでは登録されず、レコードをPublishした時点でDOIが登録されます。
4. 内容とメタデータを確認し、Publishします。

公開後の修正版は新しいバージョンとして登録します。Zenodoは各版のDOIに加えて、全バージョンをまとめて参照するConcept DOIも管理します。特定の版を引用するときは、その版固有のDOIを使います。
